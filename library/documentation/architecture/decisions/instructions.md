# Record a consequential decision

Start from a concrete unresolved choice or an already-made decision that needs explanation. Collect the constraints that affected the choice: operating environment, compatibility, cost, ownership, and expected scale.

Write a short record containing context, decision, alternatives considered, consequences, and reconsideration triggers. Compare alternatives against the same constraints; avoid describing a rejected option as obviously foolish. Separate evidence from assumptions.

Include a small before/after example when the decision changes developer or user behavior. Name the migration consequence and how readers can find the implementation. State which future observation would invalidate the choice, such as a measured workload threshold or changed compatibility requirement.

Keep the record focused on one decision. Check every link and ensure a new team member can understand the tradeoff without the original chat. Deliver the record with open questions clearly marked; do not fabricate consensus or approvers.
